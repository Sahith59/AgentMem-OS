# Luna evidence planner: development gate

October 4, 2026. This opt-in experiment keeps the existing corpus, retrieval packet and Luna answerer fixed. A Luna planning call reads only original turns already delivered in that packet and returns source IDs plus a short description of the question's requirements. The adapter appends only the selected original text, with source identity, role, observation time and hashes. It cannot recover a turn absent from the packet. Its `complete`/`uncertain` output is logged as a model claim, never certified as semantic completeness.

`benchmarks/luna_evidence_plan.py` is the offline request and application contract. `benchmarks/luna_plan_diagnostic.py` freezes an exposed 13-case semantic selection diagnostic, validates an exact package, bounds dispatch cost and attempts, preserves pending/error attempts, and reviews output against local labels. The provider request contains no expected answer or required/excluded evidence labels. Fixture source IDs are converted to opaque hashes before any request. An oracle-response test verifies transport and receipts only; it is **not** a model-quality result. The exposed fixtures cannot support a publication or generalization claim.

The current frozen 500-case source preparation passes independent source/scope verification: 500 questions, 16,210 original turns, and unchanged baseline contexts. The Luna request compatibility preflight found maximum conservative input bound 44,510 tokens-by-UTF-8-byte proxy, below the frozen 272,000 short-context price threshold. Median bound is 30,008.5. A hypothetical 500-selector-call no-retry reservation at the frozen October 4 Luna rates is $5.0923535; this is neither a request to run 500 calls nor an invoice estimate. No model selection, new answers, or English accuracy was measured by these checks.

Execution order:

1. Freeze the exact 13-case package in external memory after the implementation commit. Review its hash, 13 attempts, maximum reservation, output directory and per-case request projection. A paid authorization must name that package and cap. Previously approved paid packages do not apply.
2. Run the 13-case diagnostic once, with no automatic retry. Record every malformed output, wrong selection, incomplete response and uncertain request. Any failure stays in the denominator. Source labels are applied only after the provider returns.
3. If all 13 exposed cases pass, prepare a separate, unseen source-reviewed semantic set before claiming selector quality. Then freeze a paired English screen: same IDs, source corpus, Luna answerer, Terra grading contract and original prompt; only the focus lever differs. Add a budget-matched extra-Luna-call control to separate attention benefits from spending another call.
4. Promote only from predeclared screen and full-500 repeat evidence with an independent audit of both gains and losses. A 90% target means at least 450/500 under one fixed judge; the currently saved 425/500 Terra result is a regrade of existing answers, not a result of this planner.

The likely earliest **closure decision** is two to four focused working sessions after the selection gate and any exact paid authorizations, if the gates pass. The time to **90%** cannot be estimated from offline checks; failed gates or no meaningful paired gain require a new hypothesis and another cycle. English closure can mean a defensible, repeatable baseline below 90%, if evidence does not support the target. Sarvam remains parked under the founder's current sequence.

# Frozen SMCalFlow 2.0 conversation-control protocol

Frozen before opening the validation dialogues or measuring any scores. The archives were downloaded and hashed. Only training schema, sample training turns, official wrapper semantics and the earlier train-only inventory were inspected.

**Question.** Does the text of the immediately preceding exchange improve identification of an explicit event operation in the current turn's gold program? The primary contrast compares current user + previous user and assistant against current user alone. Endpoint is four-class macro-F1 on all eligible official validation turns. Supplementary controls are current + previous user (human input only), previous exchange only (shortcut), and one deterministic same-turn-position history permutation at inference for the fixed full model. Report separate create, update, delete and OTHER scores, count errors, micro accuracy, first/follow-up and previously unseen normalized-current-text subsets. No current assistant reply, annotations, dialogue IDs, calendar state, prior gold operation or future turn enters model features.

**Gold.** Search the current Lispress graph for callable heads CreatePreflightEventWrapper, UpdatePreflightEventWrapper, DeletePreflightEventWrapper after masking double-quoted string literals. Exactly one distinct operation type yields that label. No such head yields OTHER. Exclude turns marked skip and turns with multiple distinct types, preserving their already observable raw dialogue text as potential preceding context. Count each exclusion. An indirect revision, confirmation or query can be in OTHER. The official semantics distinguish preflight from commit, with confirmation required before writes. Under this task a label signifies an annotated operation in a program and never proves execution. [Official semantics](https://github.com/microsoft/task_oriented_dialogue_as_dataflow_synthesis/blob/bbd16fe69687b1052a7b5937ee7d20b641f2e642/README-SEMANTICS.md)

**Unit and exposure.** Use the official train/validation files, assert dialogue-ID disjointness, and check normalized full-dialogue user-text hashes for exact duplicates. Exclude validation dialogues whose full normalized user-text sequence exists in training. Report overlap separately. Report two-sided percentile 95% intervals on primary macro-F1 shift using 1,000 paired resamples of whole retained validation dialogues (seed 27112026). No validation tuning and no official test access. Source family beyond dialogue is unavailable. The training/data collection process can induce cross-dialogue templates even when complete user transcripts differ.

**Model and budget.** Each arm uses a shared deterministic hash of lowercased Unicode word/punctuation unigrams and adjacent bigrams in role-specific feature namespaces, dimension 65,536, no learned vocabulary. Keep the first 32 tokens of the current turn, first 16 of prior user and first 16 of prior assistant. L2-normalize each field separately; use no role-independent context features. Same training rows, labels, class weights (inverse training class frequency), model dimension and SGD logistic one-vs-rest optimizer, alpha 0.0001, intercept, 12 full epochs, seed 27112026, CPU and no early stopping. Unsupplied fields contribute zero. Equal maximum field budgets and optimizer passes do not imply identical actual nonzero counts, training time or inference cost. The limited linear model is an operation-routing baseline.

**Perturbation.** For each non-initial validation position, within that exact turn index, order rows by deterministic hash of dialogue ID and circularly shift by one. This pairs every eligible query with a different prior exchange in that group when the group contains two or more distinct dialogues. A singleton group remains unchanged and is counted. First turns always have empty context. Score this perturbation without retraining. Short input, prior text and the system's template style are plausible shortcuts. Prior-only results diagnose predictability without the actual current request. Report strengths and bounds even if context helps. Any edits after the first scored run require disclosure.
